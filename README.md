# موقع عالم ستائر الكويت — Astro

بُني على Astro + Tailwind CSS v4، ستاتيك بالكامل، بدون سيرفر أو قاعدة بيانات، جاهز للنشر على GitHub Pages باسم المستودع `stayerkw.github.io`.

## قبل الرفع — مهم جداً

راجع وعدّل `src/data/business.ts`: الاسم، رقم الهاتف/واتساب، الوصف. هذه القيم موجودة الآن كافتراض ويجب التأكد من صحتها قبل النشر.

المحتوى النموذجي في `src/content/` (أنواع الستائر، الخدمات، الاستخدامات، المقال التجريبي) نصوص عامة لتوضيح البنية — استبدلها بمحتوى ووصف حقيقي لعملك، وأضف صوراً حقيقية.

## التشغيل محلياً

```bash
npm install
npm run dev       # معاينة على http://localhost:4321
npm run build     # بناء الموقع في مجلد dist/
npm run preview   # معاينة نسخة الإنتاج محلياً
```

## الرفع إلى GitHub

1. أنشئ مستودعاً باسم `stayerkw.github.io` بالضبط (اسم المستودع = اسم النطاق لمواقع المستخدم على GitHub Pages).
2. ارفع كل هذه الملفات إلى فرع `main`.
3. من إعدادات المستودع → Pages → Build and deployment → Source، اختر **GitHub Actions** (الـ workflow جاهز في `.github/workflows/deploy.yml` وينشر تلقائياً عند كل push).
4. بعد أول نشر ناجح، الموقع يكون متاحاً على `https://stayerkw.github.io`.

## إضافة محتوى جديد

- نوع ستارة جديد: أضف ملف `.md` في `src/content/curtain-types/` بنفس صيغة الملفات الموجودة.
- خدمة جديدة: `src/content/services/`.
- مقال/عمل منجز: `src/content/blog/` (أضف `pubDate` واحذف `draft: true` عند النشر الفعلي).

الصفحة تُبنى تلقائياً لكل ملف — لا حاجة لتعديل الكود.

## بنية SEO المطبّقة

- HTML ستاتيك بالكامل، `lang="ar"` و`dir="rtl"`.
- Title وdescription وcanonical وOpen Graph لكل صفحة.
- JSON-LD: WebSite + LocalBusiness على كل صفحة، وProduct/Service/Article/FAQPage حسب نوع الصفحة.
- `sitemap-index.xml` يُبنى تلقائياً من `@astrojs/sitemap`.
- `robots.txt` في `public/`.
- روابط داخلية بين الرئيسية والأنواع والخدمات.
- صور بـ`loading="lazy"` و`width`/`height` لمنع CLS (أضف صورك الحقيقية إلى `public/images/` واربطها في ملفات المحتوى عبر حقل `image`).

## لوحة إدارة المنتجات (/admin)

لوحة Sveltia CMS (بديل Decap الحديث، يدعم الجوال) مجانية بلا سيرفر أو قاعدة بيانات: `/admin/`. مستضافة محلياً في `public/admin/sveltia/` (الإصدار في `VERSION.txt`)، والإعدادات في `public/admin/config.yml`، وتسجيل الدخول عبر `admin-oauth-worker`. كل تعديل يصير طلب دمج (editorial workflow) يمر بفحص الجودة قبل النشر. تدير منها: المنتجات، أعمالنا، المقالات، أنواع الستائر، الخدمات، المناطق، وصفحتي المعرض، والأسعار (`src/data/pricing.json`). فحص «الكلمة المستهدفة» جزء من `npm run lint:seo` (`scripts/keyword-check.mjs`)، وبعد تعديل `seo/keyword-master.csv` شغّل `npm run cms:keywords` لتحديث قائمتها في اللوحة.

**تحتاج إعداد لمرة واحدة فقط** (خطوات كاملة في مجلد `admin-oauth-worker/README.md` داخل هذه الحزمة):
1. إنشاء GitHub OAuth App.
2. نشر Worker صغير على Cloudflare (مجاني) يتوسط عملية تسجيل الدخول فقط — لا يخزن بياناتك.
3. تعديل رابطين في `public/admin/config.yml` (اسم المستودع ورابط الـ Worker).

بعدها تفتح `https://stayerkw.github.io/admin/` وتضيف منتجات بدون لمس الكود.

## تدابير سرعة الصفحة وLCP

لتفادي مشاكل السرعة في المواقع السابقة:

- **لا JavaScript إطلاقاً** في الصفحات العامة (Astro يصدّر HTML/CSS ثابت بالكامل، صفر hydration).
- **خط Cairo مستضاف محلياً** في `public/fonts/` (وليس من Google Fonts) — يُلغي طلب DNS/TLS لنطاق خارجي على المسار الحرج، مع `preload` لملف العنوان (700) و`font-display: swap` و`unicode-range` لتحميل نطاق عربي فقط بدل الخط كاملاً.
- **الصور تمر عبر `astro:assets`**: أي صورة تضيفها لملفات المحتوى (`image:` في الـ frontmatter) تُحوَّل تلقائياً وقت البناء لأحجام صحيحة، مع `width`/`height` صريحين (يمنع CLS) و`loading="lazy"` لكل الصور إلا أول صورة في كل صفحة قائمة والتي تأخذ `loading="eager"` + `fetchpriority="high"` (لأنها الأقرب لتكون عنصر LCP).
- **الصفحة الرئيسية بلا صورة Hero** حالياً — العنوان النصي هو عنصر LCP، وهذا أسرع من أي صورة. إن أضفت صورة Hero لاحقاً، ضعها عبر `astro:assets` وأضف لها `loading="eager"` و`fetchpriority="high"` صراحة، ولا تجعلها `lazy`.
- **صفر قاعدة بيانات وصفر سيرفر** — الصفحة تُخدَّم كملف HTML جاهز من CDN مباشرة (GitHub Pages)، فزمن الاستجابة الأول (TTFB) لا يعتمد على أي استعلام.

## سجل التعديلات المُطبّقة (SEO) — بالتفصيل

القسمان أدناه موجودان لسبب محدد: أي أداة AI (أو مطوّر) يعدّل هذا المشروع لاحقاً يحتاج يعرف **ماذا تغيّر، ولماذا، وما الذي لا يجب لمسه أو حذفه بالخطأ** أثناء إصلاح شيء آخر. كل نقطة هنا مقصودة، وليست بقايا تجربة.

### ملفات جديدة بالكامل

- **`src/data/areas.ts`** — قائمة محافظات الكويت الست وكل منطقة تابعة لكل محافظة (`kuwaitAreas`)، بالإضافة لنسخة مسطّحة `allKuwaitAreas`. هذا الملف هو **المصدر الوحيد** لأسماء المناطق في كل الموقع (الرئيسية، الفوتر، صفحة مناطق الخدمة، JSON-LD). **لا تكرّر قائمة المناطق يدوياً في مكان آخر** — أي صفحة أو مكوّن يحتاج المناطق يستورد من هنا.
- **`src/pages/areas/index.astro`** — صفحة مستقلة تعرض كل المناطق مجمّعة حسب المحافظة، مرتبطة من القائمة الرئيسية (`navigation.ts`) والفوتر والرئيسية وصفحتي الاتصال والأسعار. لا تحذفها بدون تعديل كل تلك الروابط الداخلية إليها.
- **`src/pages/404.astro`** — صفحة 404 مخصصة. **يجب أن يبقى اسم الملف `404.astro` بالضبط داخل `src/pages/` (وليس داخل مجلد فرعي)** لأن Astro/GitHub Pages يتعرفان عليها تلقائياً بهذا الاسم فقط.
- **`public/og/default.jpg`** — صورة og:image افتراضية (1200×630) تم توليدها بالألوان والاسم الإنجليزي فقط لأن الملف لم يكن موجوداً أصلاً (كان `og:image` يشير لمسار غير موجود، ما يعني معاينة مكسورة عند مشاركة أي رابط من الموقع في واتساب/تويتر). **هذه صورة بديلة مؤقتة وليست شعاراً حقيقياً** — إن استُبدلت بصورة حقيقية للنشاط، حافظ على نفس المسار `public/og/default.jpg` والمقاس 1200×630، أو عدّل `ogImage` الافتراضي في `src/layouts/BaseLayout.astro` (السطر فيه `ogImage = "/og/default.jpg"`) إذا تغيّر المسار.

### ملفات معدّلة، وسبب كل تعديل

- **`src/data/business.ts`**
  - أُزيل تعليق تحذيري قديم كان يمنع إضافة مناطق جغرافية ("لا تُضف مناطق هنا") لأن التغطية الكاملة لكل الكويت أصبحت **مؤكدة من صاحب النشاط** (وليست تخميناً) — هذا هو المبرر الوحيد لتجاوز التحذير الأصلي؛ **لا تضف أي حقيقة أخرى غير مؤكدة بنفس المنطق**.
  - أُضيف `currency: "KWD"` — يُستخدم في `offers.priceCurrency` بمخطط المنتج (Schema.astro). لا تحذفه، الحقل مُستهلَك مباشرة هناك.
  - `description` أصبحت تذكر "في جميع مناطق الكويت" — تنعكس تلقائياً كـ meta description للصفحة الرئيسية.

- **`src/components/Schema.astro`**
  - `areaServed` في LocalBusiness/Service/Product صار مبنياً من `kuwaitAreas` (قائمة الست محافظات كـ`AdministrativeArea`) بدل نص "الكويت" الثابت. **لا ترجعه لنص واحد** — القائمة أدق لمحركات البحث.
  - أُضيف دعم `image` (رابط مطلق يُبنى من `business.domain`) و`price` و`pubDate` كـ Props اختيارية.
  - **`Product`**: يضيف كائن `offers` (السعر + `priceCurrency` من `business.currency` + `availability: InStock`) **فقط إذا كان `price` موجوداً فعلاً بالمنتج** — عمداً، حتى لا يظهر سعر وهمي في نتائج جوجل (قد يُعتبر مضللاً/مشكلة Merchant listing). **لا تجعل هذا الحقل إجبارياً أو تضع قيمة افتراضية للسعر.**
  - **`Article`**: يضيف `datePublished` من `pubDate` و`image` إذا تم تمريرهما.
  - كل هذه الإضافات **اختيارية (optional)** بتصميمها — أي صفحة لا تمرّرها تستمر بالعمل بدون أخطاء.

- **`src/layouts/BaseLayout.astro`**
  - أُضيفت Props اختيارية `price` و`pubDate` وتُمرَّر مباشرة إلى `<Schema />`. أي صفحة جديدة من نوع `Product` أو `Article` يجب أن تمرّر هذه القيم من الـ frontmatter الخاص بها إذا أرادت أن يظهر السعر/تاريخ النشر في الـ JSON-LD.

- **`src/components/Breadcrumbs.astro`**
  - أصبح المكوّن يولّد `BreadcrumbList` JSON-LD تلقائياً من نفس مصفوفة `items` الظاهرة للمستخدم (يبني الروابط المطلقة عبر `business.domain`). **أي صفحة تستخدم `<Breadcrumbs items={...} />` تحصل على هذا تلقائياً — لا حاجة لإضافته يدوياً، ولا تكرّره في `Schema.astro`.**

- **`src/components/Footer.astro`**
  - الشبكة صارت `md:grid-cols-2 lg:grid-cols-4` بدل `md:grid-cols-3` بسبب إضافة عمود رابع لقائمة المحافظات (من `kuwaitAreas`) ورابط لصفحة مناطق الخدمة. إذا أضفت عموداً خامساً لاحقاً، عدّل `grid-cols` بما يناسب.

- **`src/data/navigation.ts`**
  - أُضيف رابط "مناطق الخدمة" → `/areas/`. يظهر تلقائياً بالهيدر والفوتر لأن كليهما يقرأ من `mainNav`.

- **`src/pages/index.astro`**
  - قسم جديد "نخدم جميع مناطق الكويت" يعرض شارات المحافظات الست + رابط لصفحة مناطق الخدمة.

- **`src/pages/contact/index.astro`** و **`src/pages/prices/index.astro`**
  - سطر قصير + رابط لصفحة مناطق الخدمة. تعديل نصي فقط، لا منطق جديد.

- **`src/pages/faq/index.astro`**
  - أُضيف سؤال "هل تغطون كل مناطق الكويت؟" لمصفوفة `faqs` — يدخل تلقائياً في `FAQPage` schema لأن الصفحة تمرّر `faqs={faqs}` أصلاً لـ `BaseLayout`.

- **`src/pages/curtains/[slug].astro`**
  - يجلب الآن `relatedProducts` من مجموعة `products` حيث `product.data.curtainType === entry.id` ويعرضها كبطاقات تحت المحتوى. **يعتمد على تطابق حرفي بين قيمة `curtainType` بالمنتج واسم ملف نوع الستارة (الـ id/slug)** — إذا غيّرت اسم ملف في `src/content/curtain-types/`، حدّث `curtainType` بكل المنتجات المرتبطة به.

- **`src/pages/products/[slug].astro`**
  - يمرّر `price={entry.data.price}` لـ `BaseLayout` (لتفعيل `offers` بالـ schema).
  - يجلب `curtainType` المطابق ويعرض رابط رجوع "من نوع [كذا]" أسفل الصفحة — نفس ملاحظة التطابق الحرفي أعلاه.

- **`src/pages/blog/[slug].astro`**
  - يمرّر `pubDate={entry.data.pubDate}` لـ `BaseLayout`، وأصبح تاريخ النشر ظاهراً فعلياً فوق المقال (`toLocaleDateString("ar-KW", ...)`) ليطابق ما بالـ JSON-LD. **لا تحذف عرض التاريخ من الواجهة دون حذف `pubDate` من الـ schema أيضاً** — يفضّل جوجل تطابق التاريخ الظاهر مع تاريخ الـ structured data.

- **`public/robots.txt`**
  - أُضيف `Disallow: /admin/`. لوحة الإدارة (`public/admin/index.html`) فيها أصلاً `<meta name="robots" content="noindex, nofollow">` — الإضافة هنا لتوفير Crawl Budget فقط، وليست الحماية الوحيدة. **لا تحذف أياً من الاثنين بدون الآخر.**

### جلسة لاحقة: أسعار المنتجات والصور

- **`src/components/Schema.astro`** — عرض `Product` صار يضيف `priceSpecification` من نوع `UnitPriceSpecification` بوحدة المتر المربع (`MTK`)، لأن كل الأسعار في لوحة الإدارة مُدخلة "د.ك للمتر المربع" (مؤكد من صاحب النشاط؛ كانت `MTR` بالخطأ في نسخة سابقة). **لا تحذف الوحدة:** بدونها يُقرأ الرقم كسعر القطعة كاملة. إذا أضفت لاحقاً منتجاً يُباع بالقطعة فاجعل الوحدة شرطية بحقل جديد في المنتج.
- **`src/pages/products/[slug].astro`** — صورة المنتج تُمرَّر كـ`ogImage` (عبر `getImage`، مقاس 1200×630) فتصبح صورة المشاركة وصورة الـschema بدل الصورة الافتراضية. المنتج بلا صورة يرجع تلقائياً إلى `/og/default.jpg`.
- **`src/pages/ready-roll-curtains/index.astro`** — قسم "كم سعر ستائر الرول؟" يُحسب من أقل سعر فعلي بين منتجات الرول/البلاك أوت/المكتبي غير المسودة، ويختفي إن لم يوجد سعر. السعر يظهر أيضاً على بطاقة المنتج. **لا تكتب رقماً يدوياً هنا.**

### جلسة لاحقة: الرول الجاهز الحقيقي وصور المنتجات

- **مقاسات الرول الجاهز** (مؤكدة من صاحب النشاط): ارتفاع موحّد 2.30 م، وعرض 1.50 أو 1.80 أو 2.00 م. مصدرها `sizeHeight` و`sizeWidths` في `src/data/pages/ready-roll.md` (قابلة للتعديل من اللوحة، قسم صفحات الهبوط)، وتُعرض في جدول بصفحة `/ready-roll-curtains/`. **لا تكتب المقاسات يدوياً في مكان آخر** إلا في وصف المنتجات ونص الأسئلة الشائعة.
- **كمية المخزون** لم تُنشر عمداً في الموقع (رقم يتقادم بسرعة)؛ الصفحة تقول "من المخزون" فقط.
- **9 منتجات جديدة** بصور حقيقية (7 رول جاهز + بليندين خشبيين) في `src/content/products/`، **بلا سعر** عمداً لأن الأسعار لم تُؤكَّد، فلا يُنشأ `offers` في الـschema. أضف `price` عند تأكيد السعر.
- صفحة الرول الجاهز تعرض الآن حتى 9 منتجات بدل 6.

### جلسة لاحقة: الويفي، الأسعار بالمتر المربع، ومعرض الصور

- **الأسعار (مؤكدة من صاحب النشاط):** الرول والويفي من 6 إلى 7 د.ك **للمتر المربع**؛ **الخشب حسب الطلب** بلا رقم. لذلك: منتجات الخشب بلا `price` وفيها `priceNote: "السعر حسب الطلب"` (تظهر في صفحة المنتج بدل السعر، ولا يُنشأ لها `offers`)، وباقي المنتجات `price: 6` ويُعرض "من 6 د.ك للمتر المربع".
- **`content.config.ts` + `products/[slug].astro`:** حقل اختياري `gallery` (قائمة صور) يعرض شبكة صور أسفل الصورة الرئيسية، وقابل للتعديل من لوحة الإدارة.
- **11 منتج ويفي جديد** (`curtainType: "wave"`): منتج واحد بمعرض 7 صور (الشيفون الأبيض)، و10 منتجات لكل منها صورة. الأسماء تجمع "ويفي" و"شيفون"، والأوصاف تذكر "خام" لأن الزبائن يستخدمون التسميتين.
- **`src/pages/wave-curtains/` + `src/data/pages/wave.md`:** صفحة هبوط لـ"ستائر ويفي مع شيفون"، نصوصها وأسئلتها قابلة للتعديل من اللوحة (صفحات الهبوط)، وسعرها يُحسب من أقل سعر فعلي بمنتجات الويفي. **تجنّب تكرار كلمات صفحة `/curtains/wave/`** (تستهدف "ستائر ويفي الكويت")؛ الجديدة تستهدف "ويفي مع شيفون/خام". الصفحتان مربوطتان ببعض، والجديدة مربوطة من الرئيسية وصفحات المناطق.

### أشياء لم تُلمس عمداً (ولماذا)

- لم تُضف صورة شعار حقيقية أو `sameAs` (روابط سوشيال ميديا) بـ `business.ts` لأنها غير مؤكدة من صاحب النشاط — أي إضافة لاحقة يجب أن تأتي من تأكيد فعلي، بنفس منطق قاعدة "لا تخترع بيانات نشاط" الأصلية بالملف.
- لم يُغيَّر نوع `schemaType="Product"` في صفحة نوع الستارة (`curtains/[slug].astro`) رغم أنه دلالياً أقرب لصفحة تصنيف/خدمة — هذا قرار تصميم سابق على هذه الجلسة، تم تركه كما هو لتفادي تغيير غير مطلوب.

### باقٍ يدوياً (خارج نطاق الكود)

- **Google Business Profile** (خرائط جوجل) — أهم عامل SEO محلي غير مُفعّل بعد.
- ربط Google Search Console وGA4، وتقديم `sitemap-index.xml` بعد أول نشر.
- استبدال `public/og/default.jpg` بصورة حقيقية، وإضافة صور فعلية (`image:`) لكل منتج/نوع/خدمة في `src/content/`.
- `sameAs` بـ`business.ts` إن توفرت حسابات سوشيال ميديا فعلية.
- بناء Local Citations (تسجيل النشاط بنفس الاسم/الرقم/العنوان بالضبط في أدلة كويتية).
- مقالات/أعمال منجزة دورية في `/blog/` بصور قبل/بعد حقيقية.
